# QR Screen Share

Открой страницу на компьютере (или любом устройстве-зрителе), отсканируй QR-код телефоном — телефон начнёт транслировать свой экран (Android) или камеру (iOS, из-за ограничений Safari экран транслировать нельзя) через WebRTC.

## Как это работает

- `GET /` (`view.html`) — страница зрителя: создаёт комнату, показывает QR-код со ссылкой на страницу трансляции.
- `broadcast.html?room=...` — страница, которую открывает телефон после сканирования QR. Запрашивает `getDisplayMedia` (захват экрана, Android) или `getUserMedia` (камера, iOS/фолбэк).
- Сигналинг для WebRTC (обмен SDP/ICE) идёт через WebSocket (`/ws`), сервер просто ретранслирует сообщения внутри комнаты.
- Видео передаётся напрямую между устройствами по WebRTC (peer-to-peer), сервер не проксирует сам поток.

## Запуск локально

```bash
npm install
npm start
```

Сервер поднимется на `http://localhost:3000`.

**Важно:** `getDisplayMedia`/`getUserMedia` в браузере требуют HTTPS (кроме `localhost`). Чтобы протестировать с реального телефона по локальной сети, нужен HTTPS-туннель, например:

```bash
npx localtunnel --port 3000
# или
ngrok http 3000
```

Открой полученный HTTPS-адрес на компьютере — оттуда и сканируй QR.

## Деплой

Подойдёт любой хостинг с поддержкой Node.js и WebSocket (Render, Fly.io, Railway и т.п.). Статического хостинга (Vercel serverless, GitHub Pages) недостаточно — нужен постоянный WebSocket-сервер для сигналинга.

## Ограничения

- **iOS**: Safari (и любой браузер на iOS, все на движке WebKit) не поддерживает захват экрана из веб-страницы. На iOS транслируется камера, а не экран. Полноценный захват экрана на iOS возможен только через нативное приложение с ReplayKit.
- **Android**: захват экрана работает в Chrome через `getDisplayMedia`.
- Для соединения между устройствами в разных сетях за NAT публичного STUN-сервера (Google) обычно достаточно, но в некоторых сетях (корпоративный NAT, мобильный оператор с симметричным NAT) может понадобиться TURN-сервер — в проекте он не настроен.
